# Brand Systems

Use this file whenever the request is tied to a specific brand, so outputs stay aligned with stored strategy instead of inventing a new one each time.

## Where the brand system lives

Look in the student's project, in this order:

1. `./marca/brand-profile.md` — identity, audience, offer, voice, visual identity, pillars, hashtags.
2. `./marca/style-bible.md` — visual rules for images and video (mascots, spokespeople, lighting).
3. `./marca/hooks-ctas-claims.md` — approved hooks, CTAs and claims with their proof.
4. `./marca/playbooks/` — one playbook per channel (ventas, pauta, redes, landing, presentaciones).
5. The student's Obsidian vault: `Memoria/Marcas/<Marca>/` if they use the memory system.

If none exist, create `./marca/brand-profile.md` from the `instagram-content-suite` template before producing deliverables.

## Routing

- Sales or messaging -> brand profile (offer, objections) + `playbooks/ventas.md`
- Ads or social -> `playbooks/pauta.md` / `playbooks/redes.md` + hooks library
- Landing pages -> `playbooks/landing.md` + offer + proof
- Decks -> `playbooks/presentaciones.md`
- Visual generation -> `style-bible.md` + visual identity section of the profile

## Rule

If a brand system exists, use it instead of inventing a fresh strategy. When a new decision is confirmed (tone, offer, claim, audience), update the brand files so the next session starts from it.
